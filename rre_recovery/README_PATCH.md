# RRE persistent candidate-isolation patch

## Change
`rre_persistent.py` now verifies candidates against a detached copy before any live mutation. Only the exact candidate rule set `{"missing_evidence": "report_unknown"}` passes the current held-out contract. Rejected/malformed proposals append a rejection audit event but do not change live rules, version, identity, or durable state. `snapshot()` now deep-copies nested state so callers retain a stable historical record.

## Reproduction
Run from this directory:

```sh
python test_rre_minimal.py
python -m unittest -v test_rre_persistent.py
python run_milestone.py
```

Execution recorded in `execution_results_patch.txt`. The milestone runner reported all commands passed; its held-out evaluator was 8/8 and audit chain verified 22 events. The persistent suite reports 11 tests passing, including four named adversarial isolation/snapshot regressions.

## Scope and limits
The root `rre_minimal.py` and `test_rre_minimal.py` were not edited. Other milestone artifacts were regenerated by the existing milestone runner, so byte-for-byte reproduction of the previously recorded report/audit was not established. No external independent evaluator was rerun in this environment. Atomic replacement of the state file is exercised by the existing implementation, but crash/power-loss behavior across filesystem/platform combinations is not proven. The isolation tests cover the specified malformed, always-refuse, and revert-to-guess candidates; they do not prove safety for every possible Python object, concurrent writer, or hostile filesystem.
